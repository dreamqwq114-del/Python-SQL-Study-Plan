# SQL 初学者术语表

本文件用于查名词，不替代各章 `lesson.md`。第一次遇到陌生词时，先读对应章节的解释；仍不清楚再回到这里查。

每个术语都回答三件事：

1. 它是什么；
2. 最容易和什么混淆；
3. 应到哪一章练习。

## 一、数据库中的基本对象

### 数据库（database）

- 通俗定义：按一个用途集中保存表、关系和数据的容器。
- 本课程中的实例：`mysql_beginner_practice`。
- 易混点：数据库不是某一张表；执行修改前必须先确认当前数据库。
- 对应位置：`00_setup`、README。

### 模式（schema）

- 通俗定义：用于组织数据库对象的命名空间。
- MySQL 中怎么理解：在本课程的基础用法中，可以把 schema 和 database 看成同一层级。
- 易混点：其他数据库产品可能严格区分 schema 与 database，本课程不展开。
- 对应位置：`00_setup/verify_database.sql` 中的 `information_schema` 查询。

### 表（table）

- 通俗定义：按固定列保存同一类记录的数据结构。
- 本课程中的实例：`employees` 表保存员工，`projects` 表保存项目。
- 易混点：表名表示数据来源，不代表结果一定返回表中所有列。
- 对应章节：第 1 章。

### 行（row）

- 通俗定义：表中的一条完整记录。
- 本课程中的实例：`employees` 的一行代表一名员工。
- 易混点：JOIN 后的一行可能表示“员工与项目的一次组合”，不再只代表员工。
- 验证方法：先用一句话说清“结果中的一行代表什么”。
- 对应章节：第 1、5、6 章。

### 列（column）

- 通俗定义：同类记录共有的一个属性。
- 本课程中的实例：`employee_name` 是员工姓名列，`salary` 是薪资列。
- 易混点：结果列可以来自原字段、别名、计算或聚合，不一定是原表中的固定字段。
- 对应章节：第 1 章。

### 字段

- 通俗定义：初学阶段通常把它当作“列”的同义词。
- 易混点：严格的数据建模语境中可能区分字段和值，本课程统一用“列”解释结果结构。
- 对应章节：第 1 章。

### 结果集（result set）

- 通俗定义：一条查询运行后返回的列和行。
- 易混点：结果集只是查看到的结果，不会因为 `SELECT` 自动写回原表。
- 验证方法：检查列数、行数、`NULL`、重复、排序和无匹配记录。
- 对应章节：第 1 章和 README。

### 查询（query）

- 通俗定义：向数据库提出问题并读取结果的 SQL。
- 最小例子：

```sql
SELECT employee_name
FROM employees;
```

- 易混点：查询能运行只代表语法可执行，不代表它回答了题目。
- 对应章节：第 1～8、10 章。

### SQL 语句（statement）

- 通俗定义：以分号结束的一条完整 SQL 指令。
- 本课程中的类型：查询语句、数据修改语句、事务控制语句。
- 易混点：一个代码块中可能有多条语句，应按课程要求逐条或整块运行。
- 对应章节：全课程。

### 数据类型（data type）

- 通俗定义：规定一列可以保存什么形式的数据。
- 本课程中的实例：`INT` 整数、`DECIMAL` 精确小数、`VARCHAR` 文本、`DATE` 日期。
- 易混点：文本 `'2026-01-01'` 可按日期比较，但文本、数字和日期仍不是同一种类型。
- 只读观察方法：在练习库中运行 `DESCRIBE employees;`，查看各列的 `Type`，不会修改数据。
- 本课程要求：能读懂常见类型并正确比较或转换即可，不要求独立设计表结构或手写建表 DDL。
- 对应章节：`00_setup`、第 3、8 章。

## 二、读取和筛选

### SELECT

- 通俗定义：决定结果要显示哪些列或表达式。
- 易混点：`SELECT *` 返回全部列；指定列只返回题目要求的部分。
- 对应章节：第 1 章。

### FROM

- 通俗定义：决定数据从哪张表或临时结果中读取。
- 易混点：`SELECT` 决定显示内容，`FROM` 决定来源。
- 对应章节：第 1 章。

### 别名（alias）

- 通俗定义：给结果列或表起一个只在当前查询中使用的短名字。
- 基本语法：`salary AS employee_salary`、`employees AS e`。
- 易混点：别名不会修改原表名或原字段名。
- 对应章节：第 1、5 章。

### 表达式（expression）

- 通俗定义：由字段、常量、运算符或函数组成并产生一个值的写法。
- 本课程中的实例：`budget * 0.05`。
- 易混点：计算列只出现在结果中，不会自动保存。
- 对应章节：第 1 章。

### 条件 / 谓词（condition / predicate）

- 通俗定义：对每一行作出“保留或不保留”判断的表达式。
- 本课程中的实例：`salary >= 12000`。
- 易混点：条件写法合法也可能逻辑不正确，尤其是混合 `AND` 和 `OR` 时。
- 对应章节：第 2 章。

### WHERE

- 通俗定义：在分组和聚合之前筛选原始行。
- 易混点：分组后的条件使用 `HAVING`；不能用 `WHERE COUNT(*) > 2`。
- 对应章节：第 2、4 章。

### NULL

- 通俗定义：值未知、缺失或尚未填写，不等于 0，也不等于空字符串。
- 基本语法：`IS NULL`、`IS NOT NULL`。
- 易混点：不能写 `= NULL`；`COUNT(column)` 不统计该列为 `NULL` 的行。
- 对应章节：第 2、4、6、7、8 章。

### DISTINCT

- 通俗定义：去除结果中重复的列值组合。
- 易混点：它不删除原表数据；查询多列时按整组列判断重复。
- 对应章节：第 1 章。

### ORDER BY

- 通俗定义：规定结果的排序规则。
- 基本语法：`ORDER BY salary DESC, employee_id ASC`。
- 易混点：没有 `ORDER BY` 的 `LIMIT 3` 不等于“最高三条”。
- 对应章节：第 1、3 章。

### 稳定排序

- 通俗定义：主排序值相同时，再用第二排序列明确先后顺序。
- 本课程中的实例：薪资相同时按员工编号升序。
- 易混点：数据库不会保证相同排序值之间天然保持固定顺序。
- 对应章节：第 1、3 章。

### LIMIT

- 通俗定义：限制结果最多返回多少行。
- 易混点：它只限制数量，不定义“最高、最低、最新或最早”。
- 对应章节：第 1 章。

## 三、聚合和分组

### 聚合函数（aggregate function）

- 通俗定义：把多行数据汇总成一个值的函数。
- 本课程中的函数：`COUNT`、`SUM`、`AVG`、`MIN`、`MAX`。
- 易混点：除 `COUNT(*)` 外，多数聚合函数会忽略输入中的 `NULL`。
- 对应章节：第 4 章。

### COUNT(*) 与 COUNT(column)

- `COUNT(*)`：统计结果中的行数，包括某些列为 `NULL` 的行。
- `COUNT(column)`：只统计该列非 `NULL` 的行。
- 易混点：统计全部项目时使用 `COUNT(end_date)` 会漏掉结束日期为空的项目。
- 对应章节：第 4、6 章。

### GROUP BY

- 通俗定义：先按一个或多个列分组，再对每组分别聚合。
- 易混点：结果中的一行通常代表一个组，不再代表一条原始记录。
- 验证方法：检查组数、每组计数以及各组计数之和。
- 对应章节：第 4 章。

### HAVING

- 通俗定义：在分组和聚合完成后筛选组。
- 易混点：`WHERE` 筛原始行，`HAVING` 筛聚合后的组。
- 对应章节：第 4 章。

## 四、表之间的关系和 JOIN

### 主键（primary key）

- 通俗定义：能唯一标识表中一行的列或列组合。
- 本课程中的实例：`employees.employee_id`。
- 易混点：主键值不能在同一表中重复，也不能是 `NULL`。
- 对应章节：`00_setup`、第 5 章。

### 外键（foreign key）

- 通俗定义：保存另一张表主键值，用来表达两张表之间的关系。
- 本课程中的实例：`employees.department_id` 指向 `departments.department_id`。
- 易混点：外键列与被连接的主键含义必须一致，不能只因为类型相同就连接。
- 对应章节：`00_setup`、第 5 章。

### JOIN

- 通俗定义：根据关联条件，把多张表中有关联的行组合到同一结果中。
- 易混点：JOIN 后的行数取决于关系数量，不能默认“一张表一行，结果仍一行”。
- 对应章节：第 5、6 章。

### 连接条件（JOIN condition）

- 通俗定义：写在 `ON` 后，说明两张表的哪些值必须对应。
- 本课程中的实例：`d.department_id = e.department_id`。
- 易混点：遗漏或写错连接条件可能产生大量无意义组合。
- 对应章节：第 5 章。

### 连接键（join key）

- 通俗定义：连接条件中用于对应两张表记录的列，例如 `employees.department_id` 和 `departments.department_id`。
- 易混点：连接键经常是“外键对应主键”，但并非所有 JOIN 都强制如此；列名也不一定相同，关键是两列的业务含义能够正确对应。
- 验证方法：先确认一行代表什么，再检查连接后是否漏行、重复或出现无意义组合。
- 对应章节：第 5、6 章。

### INNER JOIN

- 通俗定义：只保留左右两边都能匹配的组合。
- 易混点：左表中没有匹配的记录会消失。
- 对应章节：第 5 章。

### LEFT JOIN

- 通俗定义：保留左表全部记录；右表无匹配时，右表列显示 `NULL`。
- 易混点：在 `WHERE` 中要求右表字段等于某值，可能再次删除无匹配行。
- 对应章节：第 6 章。

### 一对一

- 通俗定义：左表一行最多对应右表一行。
- 本课程中的实例：一个项目最多对应一条 `project_metrics`。
- 对应章节：第 6 章。

### 一对多

- 通俗定义：左表一行可以对应右表多行。
- 本课程中的实例：一个项目可以有多条员工参与记录。
- 易混点：JOIN 后项目名称重复可能是正确结果，不是脏数据。
- 对应章节：第 5、6 章。

### 多对多

- 通俗定义：两边都可以对应多行，通常通过中间表表示。
- 本课程中的实例：员工与项目通过 `employee_projects` 形成多对多关系。
- 对应章节：第 6 章。

### 重复与重复计数

- 通俗定义：同一个业务对象因一对多 JOIN 在结果中出现多次。
- 易混点：直接 `SUM(p.budget)` 可能把同一项目预算重复相加。
- 常用检查：先查看连接明细，再决定是否使用 `COUNT(DISTINCT ...)` 或减少不需要的 JOIN。
- 对应章节：第 6、10 章。

## 五、分类、子查询和临时结果

### CASE WHEN

- 通俗定义：按条件为每一行生成分类或显示值。
- 易混点：条件从上到下判断，前面的条件可能先匹配。
- 对应章节：第 7 章。

### 子查询（subquery）

- 通俗定义：写在另一条 SQL 内部的查询。
- 易混点：内部查询返回一列、多行还是一个值，决定外层可以怎样使用。
- 对应章节：第 7 章。

### 标量子查询（scalar subquery）

- 通俗定义：预期只返回一个值的子查询。
- 本课程中的实例：计算平均薪资，再筛选高于平均薪资的员工。
- 易混点：返回多行时不能当作一个普通值比较。
- 对应章节：第 7 章。

### IN 子查询

- 通俗定义：子查询返回一列多个值，外层检查某个值是否在其中。
- 易混点：子查询应只返回用于比较的一列。
- 对应章节：第 7 章。

### CTE

- 全称：Common Table Expression，公共表表达式。
- 通俗定义：使用 `WITH` 给当前 SQL 中的一段临时查询结果起名。
- 易混点：本课程只学习非递归 CTE；它不是永久表。
- 对应章节：第 8 章。

### EXISTS / NOT EXISTS

- 通俗定义：判断关联子查询是否至少找到一行，或一行也找不到。
- 易混点：它关心“是否存在”，不关心子查询具体返回哪些列。
- 对应章节：第 8 章。

### CAST

- 通俗定义：把查询结果中的值转换成另一种数据类型。
- 易混点：只改变本次结果的表示，不修改原表字段类型。
- 对应章节：第 8 章。

### COALESCE

- 通俗定义：从左到右返回第一个非 `NULL` 的值。
- 本课程中的用途：把缺失显示为“未填写”或 0。
- 易混点：只改变结果显示，不会填回原表。
- 对应章节：第 8、10 章。

## 六、数据修改和事务

### INSERT

- 通俗定义：向表中新增一行或多行。
- 易混点：必须满足主键、外键和非空约束。
- 对应章节：第 9 章。

### UPDATE

- 通俗定义：修改已经存在的行。
- 安全顺序：先用相同 `WHERE` 执行 `SELECT`，再放进事务修改和验证。
- 易混点：遗漏 `WHERE` 会影响整张表。
- 对应章节：第 9 章。

### DELETE

- 通俗定义：删除满足条件的整行。
- 易混点：它不是“清空某一个字段”；遗漏 `WHERE` 会删除整表数据。
- 对应章节：第 9 章。

### 事务（transaction）

- 通俗定义：把一组修改当作一个可确认或可撤销的工作单元。
- 本课程开始方式：`START TRANSACTION`。
- 易混点：事务不能代替准确的 `WHERE`，只能给验证和撤销提供机会。
- 对应章节：第 9 章。

### ROLLBACK

- 通俗定义：撤销当前事务中尚未提交的修改。
- 本课程规则：所有修改练习默认使用 `ROLLBACK`。
- 易混点：已经 `COMMIT` 的内容不能靠普通 `ROLLBACK` 撤销。
- 对应章节：第 9 章。

### COMMIT

- 通俗定义：永久保存当前事务中的修改并结束该事务。
- 本课程规则：教学示例不靠 `COMMIT` 保存修改数据。
- 易混点：执行前必须确认数据库、目标行、影响行数和验证结果。
- 对应章节：第 9 章。

## 七、综合项目中的业务名词

### 项目经理

- 通俗定义：对项目负责的员工，通过 `projects.project_manager_id` 关联员工编号。
- 易混点：项目经理与项目参与人员不是同一个关系；没有经理的项目仍应在某些 LEFT JOIN 报表中保留。
- 对应章节：第 5、10 章。

### 项目状态

- 本课程中的值：进行中、已完成、暂停、待启动。
- 易混点：状态是文本分类，不是日期；是否结束还可能需要结合 `end_date` 检查。
- 对应章节：第 2、3、7、10 章。

### 管理费（management fee）

- 通俗定义：项目指标表中的管理费比例。
- 易混点：当前数据是小数比例，例如 `0.20`；显示为百分比时需要计算。
- 对应章节：第 1、8、10 章。

### 投资收益率（ROI）

- 全称：Return on Investment。
- 通俗定义：表示项目投资收益相对投入的比例，本课程字段是 `investment_return_rate`。
- 易混点：`0.0815` 表示比例值，不是已经带 `%` 的文本。
- 对应章节：第 8、10 章。

### 电压等级

- 通俗定义：项目指标中的电气等级分类，例如 `380V`、`10kV`、`110kV`。
- 易混点：它是文本分类，不应直接当普通数字比较；部分项目可能为 `NULL`。
- 对应章节：第 2、6、8、10 章。

## 最后自检

遇到一个名词时，应能回答：

1. 它对应表、行、列、条件、关系、结果还是修改控制？
2. 它会不会改变原始数据？
3. 它怎样影响返回列数和行数？
4. 它怎样处理 `NULL` 和重复？
5. 我应该到哪一章重新运行示例？

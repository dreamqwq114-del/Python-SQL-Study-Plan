# 第 7 章：CASE 和简单子查询

## 1. 本章目标

- 使用 `CASE WHEN` 根据条件生成分类结果。
- 用简单 `CASE` 清楚标记 `NULL`。
- 理解只返回一个值的标量子查询。
- 使用标量子查询和 `IN` 子查询完成常见筛选。
- 暂时不学习复杂嵌套、相关子查询或递归查询。

## 2. 前置知识

需要会使用 `SELECT`、`WHERE`、`ORDER BY`、聚合函数、`IN` 和 `IS NULL`。

## 3. 核心概念

### CASE WHEN

#### 它解决什么问题

`CASE WHEN` 根据每行数据满足的条件，在查询结果中生成一个分类或说明。

#### 最基本语法

```sql
CASE
    WHEN condition_1 THEN result_1
    WHEN condition_2 THEN result_2
    ELSE other_result
END AS result_name
```

#### 怎么理解

数据库从上到下检查条件，遇到第一个为真的条件就返回对应结果。`ELSE` 处理没有命中前面条件的情况。

#### 常见错误

- 忘记写 `END`。
- 条件顺序错误，使后面的分支永远不会命中。
- 不同分支返回含义不一致的值。

#### 如何验证结果

抽查每个分界值和每个分类，确认列数、行数不变，并检查是否出现意外 `NULL`。

### 使用 CASE 处理 NULL

#### 它解决什么问题

可以把不易理解的 `NULL` 转换为“未设置”等清楚标签，但不会修改原数据。

#### 最基本语法

```sql
CASE
    WHEN column_name IS NULL THEN '未设置'
    ELSE '已设置'
END
```

#### 怎么理解

必须使用 `IS NULL`，不能使用 `= NULL`。这个转换只影响查询显示。

#### 常见错误

- 写成 `column_name = NULL`。
- 误以为显示标签会写回原表。
- 没有检查非空分支。

#### 如何验证结果

分别抽查原字段为空和非空的行，并确认原字段仍保持原值。

### 标量子查询

#### 它解决什么问题

标量子查询先算出一个值，外层查询把这个值用于显示或比较。

#### 最基本语法

```sql
SELECT ...
FROM table_name
WHERE number_column > (
    SELECT AVG(number_column)
    FROM table_name
);
```

#### 怎么理解

括号内查询必须只返回一行一列。外层查询可以把它当成一个数值使用。

#### 常见错误

- 子查询返回多行，无法与一个值比较。
- 忘记子查询外的括号。
- 内外层字段来自错误的表。

#### 如何验证结果

先单独运行子查询，确认只有一行一列；再检查外层每行是否满足比较条件。

### 高于平均值

#### 它解决什么问题

聚合函数先计算整体平均值，外层查询再找出高于该值的明细行。

#### 最基本语法

```sql
WHERE value_column > (
    SELECT AVG(value_column)
    FROM table_name
)
```

#### 怎么理解

平均值是一条汇总结果，外层仍返回具体明细。`>` 不包含刚好等于平均值的行。

#### 常见错误

- 在同一层的 `WHERE` 直接使用 `AVG`。
- 把 `>` 写成 `>=`，改变题意。
- 没有先核对平均值。

#### 如何验证结果

单独记录平均值，检查返回的最小值是否仍高于它，并确认没有遗漏更高值。

### IN 子查询

#### 它解决什么问题

子查询返回一列允许值，外层查询判断某字段是否属于这组值。

#### 最基本语法

```sql
WHERE key_column IN (
    SELECT key_column
    FROM other_table
    WHERE ...
)
```

#### 怎么理解

子查询可以返回多行，但必须只返回一列供 `IN` 比较。重复值不会让外层同一行重复出现。

#### 常见错误

- 子查询返回两列。
- 内外层比较字段含义不一致。
- 把 `IN` 子查询误当成标量子查询。

#### 如何验证结果

先运行子查询检查允许值，再核对外层每行的比较字段是否在这组值中。

## 4. 可运行示例

## 示例 1：按预算给项目分类

### 学习目标

使用有顺序的多个 `WHEN` 生成预算等级。

### 运行前预测

1. 结果会新增哪一列？
2. 预算等于 800000 时属于哪一类？
3. 原预算会不会被修改？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name,
    budget,
    CASE
        WHEN budget >= 800000 THEN '高预算'
        WHEN budget >= 500000 THEN '中预算'
        ELSE '低预算'
    END AS budget_level
FROM projects
ORDER BY
    budget DESC,
    project_id ASC;
```

### 运行后观察

1. 每行是否都有预算等级？
2. 500000 和 800000 两个边界如何分类？
3. 为什么高预算条件要写在中预算条件前？

### 结果特征

- 结果有三列；
- 每个项目一行；
- 分类只影响查询结果，不修改 `budget`。

### 最小修改任务

把高预算门槛改为 900000，中预算门槛保持 500000。

### 本例常见错误

- 忘记 `END`；
- 先写 `budget >= 500000`，使高预算分支无法命中；
- 漏写 `ELSE`。

## 示例 2：标记项目结束日期是否设置

### 学习目标

用 `CASE` 和 `IS NULL` 把空值显示为清楚标签。

### 运行前预测

1. `end_date` 为 `NULL` 时显示什么？
2. 是否会修改原结束日期？
3. `end_date = NULL` 能否正确判断？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_id,
    project_name,
    end_date,
    CASE
        WHEN end_date IS NULL THEN '未设置'
        ELSE '已设置'
    END AS end_date_status
FROM projects
ORDER BY project_id;
```

### 运行后观察

1. 空日期是否全部显示“未设置”？
2. 非空日期是否全部显示“已设置”？
3. 原 `end_date` 列是否仍含 `NULL`？

### 结果特征

- 结果有四列；
- 每个项目一行；
- 标签列不改变原始日期。

### 最小修改任务

把标签改为“待确定”和“已确定”。

### 本例常见错误

- 使用 `= NULL`；
- 忘记 `ELSE`；
- 以为标签会填充原字段。

## 示例 3：同时显示员工薪资和公司平均薪资

### 学习目标

观察只返回一个值的标量子查询。

### 运行前预测

1. 子查询返回几行几列？
2. 平均薪资会不会在每名员工行中重复显示？
3. 外层查询返回几行？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    salary,
    (
        SELECT AVG(salary)
        FROM employees
    ) AS company_avg_salary
FROM employees
ORDER BY employee_id;
```

### 运行后观察

1. `company_avg_salary` 是否每行相同？
2. 子查询单独运行时是否只有一个值？
3. 外层行数是否仍等于员工数？

### 结果特征

- 结果有三列；
- 每名员工一行；
- 平均薪资作为同一个标量值重复显示。

### 最小修改任务

改为显示项目名称、预算和所有项目的平均预算。

### 本例常见错误

- 子查询返回员工明细而不是平均值；
- 漏掉括号；
- 把平均值误认为原表新增字段。

## 示例 4：查询薪资高于平均值的员工

### 学习目标

用标量子查询的平均值筛选外层明细。

### 运行前预测

1. 返回员工数会不会少于总员工数？
2. 等于平均薪资的员工会不会出现？
3. 结果中每个薪资应与什么比较？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_id,
    employee_name,
    salary
FROM employees
WHERE salary > (
    SELECT AVG(salary)
    FROM employees
)
ORDER BY
    salary DESC,
    employee_id ASC;
```

### 运行后观察

1. 最低返回薪资是否仍高于平均值？
2. 结果是否按薪资降序？
3. 如果把 `>` 改成 `<`，含义如何变化？

### 结果特征

- 结果有三列；
- 只包含严格高于平均薪资的员工；
- 相同薪资按员工编号稳定排序。

### 最小修改任务

改为查询薪资低于公司平均值的员工，并按薪资升序、员工编号升序排列。

### 本例常见错误

- 在外层 `WHERE` 直接写 `salary > AVG(salary)`；
- 使用 `>=` 改变题意；
- 子查询漏写 `FROM`。

## 示例 5：查询高预算项目所属部门的员工

### 学习目标

使用 `IN` 子查询返回一组部门编号。

### 运行前预测

1. 子查询返回几列？
2. 同一部门有多个高预算项目时，员工会不会重复？
3. 外层比较的是哪两个同义字段？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_id,
    employee_name,
    department_id
FROM employees
WHERE department_id IN (
    SELECT department_id
    FROM projects
    WHERE budget >= 900000
)
ORDER BY employee_id;
```

### 运行后观察

1. 先单独运行子查询会得到哪些部门编号？
2. 每名员工是否只出现一次？
3. 外层员工的部门编号是否都在子查询结果中？

### 结果特征

- 结果有三列；
- 只包含高预算项目所属部门的员工；
- 子查询重复部门编号不会复制外层员工行。

### 最小修改任务

把高预算条件改为 `budget >= 1000000`。

### 本例常见错误

- 子查询同时返回部门编号和项目名称；
- 外层用员工编号与部门编号比较；
- 忘记子查询的括号。

## 5. 容易混淆的地方

- `CASE` 从上到下匹配第一个为真的分支，条件顺序很重要。
- 判断空值必须使用 `IS NULL`，不能使用 `= NULL`。
- 标量子查询必须只返回一行一列。
- 高于平均值通常要在子查询中先计算平均值，再由外层筛选。
- `IN` 子查询可以返回多行，但只能返回一列供外层比较。

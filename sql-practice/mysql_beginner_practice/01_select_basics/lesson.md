# 第 1 章：SELECT 基础

## 本章计时建议

- 一次 45～60 分钟是一个学习时段，不保证完成整章；
- 时段 A：核心概念、全部示例和最小修改，约 25～35 分钟；
- 时段 B：8 道练习至少 40 分钟，错题整理另需 5～10 分钟；
- 没完成就下次继续，不要为了赶时间提前看答案。

## 1. 本章目标

- 使用 `SELECT` 和 `FROM` 从一张表读取数据。
- 只选择题目要求的列，并使用 `AS` 给结果列起别名。
- 使用 `DISTINCT` 去除查询结果中的重复组合。
- 使用计算列、`ORDER BY` 和 `LIMIT` 得到可验证的结果。
- 暂时不学习筛选、分组和表连接。

## 2. 前置知识

无。开始前只需完成 `00_setup`，并确认当前数据库是 `mysql_beginner_practice`。

## 3. 核心概念

### SELECT 与 FROM

#### 它解决什么问题

`SELECT` 决定结果显示哪些列，`FROM` 决定数据来自哪张表。

#### 最基本语法

```sql
SELECT column_name
FROM table_name;
```

#### 怎么理解

- `SELECT` 后写需要显示的列。
- `FROM` 后写存放这些列的表。
- 分号表示一条 SQL 结束。

#### 常见错误

- 字段名或表名拼错。
- 忘记写 `FROM`。
- 题目只要两列，却使用 `SELECT *`。

#### 如何验证结果

先检查返回列是否与题目一致，再检查行数是否合理。还要留意 `NULL` 和重复值。

### SELECT * 与指定列

#### 它解决什么问题

`SELECT *` 能快速查看表的全部列；正式查询通常只选择真正需要的列。

#### 最基本语法

```sql
SELECT *
FROM table_name;
```

#### 怎么理解

星号代表表中的全部列。它适合初次观察小表，不代表每道题都应该使用。

#### 常见错误

- 把“能看到数据”误当成“满足题目要求”。
- 表新增列后，结果结构也跟着变化。

#### 如何验证结果

查看结果表的列数和列名，确认是否返回了题目没有要求的列。

### AS 别名

#### 它解决什么问题

`AS` 让结果列标题更清楚，但不会修改原表字段名。

#### 最基本语法

```sql
SELECT
    column_name AS new_name
FROM table_name;
```

#### 怎么理解

`AS` 后的名字只在本次结果中使用。再次查看表结构，原字段名仍然不变。

#### 常见错误

- 误以为别名会永久修改字段名。
- 把别名写在 `FROM` 后。

#### 如何验证结果

检查结果列标题，再检查原表结构是否保持不变。

### 计算列

#### 它解决什么问题

计算列使用现有字段生成新结果，不会把结果自动写回原表。

#### 最基本语法

```sql
SELECT
    number_column,
    number_column * 0.10 AS calculated_value
FROM table_name;
```

#### 怎么理解

数据库对返回的每一行进行计算，`AS` 为计算结果设置容易理解的标题。

#### 常见错误

- 把 `10%` 直接写入 SQL。
- 忘记给计算列起别名。

#### 如何验证结果

任选一行手工核对计算，并重新查询原字段确认它没有变化。输入为 `NULL` 时，计算结果也可能是 `NULL`。

### DISTINCT

#### 它解决什么问题

`DISTINCT` 去除查询结果中重复的列值组合，不会删除原表数据。

#### 最基本语法

```sql
SELECT DISTINCT column_name
FROM table_name;
```

#### 怎么理解

`DISTINCT` 针对 `SELECT` 后所有列的组合去重。查询一列时检查单列重复，查询多列时检查整组值是否重复。

#### 常见错误

- 以为 `DISTINCT` 会删除表中的原始数据。
- 同时查询多列时，误以为 `DISTINCT` 只处理第一列。

#### 如何验证结果

检查去重后的结果是否仍有重复组合，并再次查询原表确认记录没有被删除。

### ORDER BY 与 LIMIT

#### 它解决什么问题

`ORDER BY` 决定结果顺序，`LIMIT` 限制返回行数。二者一起使用，才能明确“前几条”指什么。

#### 最基本语法

```sql
SELECT column_name
FROM table_name
ORDER BY sort_column DESC
LIMIT 3;
```

#### 怎么理解

数据库先按 `ORDER BY` 排序，再保留 `LIMIT` 指定的行数。`ASC` 是升序，`DESC` 是降序。

#### 常见错误

- 只写 `LIMIT`，却把结果理解成“最高的前几条”。
- 把 `DESC` 写在 `LIMIT` 后面。
- 排序值相同时没有增加第二排序列，导致顺序不稳定。

#### 如何验证结果

检查行数是否等于限制值、排序方向是否正确，以及相同排序值之间是否有明确顺序。

## 4. 可运行示例

## 示例 1：查询员工姓名和职位

### 学习目标

理解如何只查询需要的列，而不是使用 `SELECT *`。

### 运行前预测

1. 结果会有多少列？
2. 是否会返回所有员工？
3. `employee_id` 会不会出现在结果中？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    job_title
FROM employees;
```

### 运行后观察

1. 实际返回多少列？
2. 为什么没有 `employee_id`？
3. 是否每名员工都占一行？

### 结果特征

- 应返回所有员工；
- 只有 `employee_name` 和 `job_title` 两列；
- 不要求逐行记住完整结果。

### 最小修改任务

将查询改成同时显示 `employee_name`、`job_title` 和 `salary`。

### 本例常见错误

- 字段名拼错；
- 忘记 `FROM`；
- 使用 `SELECT *`，返回了题目不需要的列。

## 示例 2：观察 SELECT * 返回的列

### 学习目标

实际比较“全部列”和“指定列”，知道能运行不代表列数正确。

### 运行前预测

1. `departments` 的全部列是否都出现？
2. 题目只要部门名称时，结果会不会包含多余列？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT *
FROM departments;
```

### 运行后观察

1. 实际返回了哪些列？
2. `city` 中是否出现 `NULL`？
3. 为什么只需要部门名称时不应使用星号？

### 结果特征

- 返回 `departments` 的全部列和全部部门；
- 结果包含题目可能没有要求的列；
- 查询不会修改原表。

### 最小修改任务

改成只显示 `department_id` 和 `department_name`。

### 本例常见错误

- 只看行数，不检查列数；
- 认为 `SELECT *` 永远满足题目；
- 误以为查询会修改数据。

## 示例 3：给项目列起别名

### 学习目标

理解 `AS` 只改变结果列标题。

### 运行前预测

1. 结果会有多少列？
2. 结果列标题是否仍叫 `project_name`？
3. 原表字段名会不会被修改？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name AS project,
    project_status AS status
FROM projects;
```

### 运行后观察

1. 结果列标题是什么？
2. 再次查看表结构时，原字段名是否仍然存在？
3. 每个项目是否仍只返回一行？

### 结果特征

- 结果只有 `project` 和 `status` 两列；
- 应返回全部项目；
- `AS` 不会修改表结构。

### 最小修改任务

增加 `budget AS project_budget`，使结果显示三列。

### 本例常见错误

- 把别名写在 `FROM` 后；
- 误以为别名会永久修改字段名；
- 别名与原字段名之间漏写空格或 `AS`。

## 示例 4：查看不重复的职位

### 学习目标

理解 `DISTINCT` 去除的是查询结果中的重复值。

### 运行前预测

1. 结果行数会不会少于员工总数？
2. 相同职位是否会重复出现？
3. 员工表中的数据会不会被删除？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT DISTINCT job_title
FROM employees;
```

### 运行后观察

1. 每个职位出现几次？
2. 去重后的行数和员工总数有什么关系？
3. 再查询员工表时，员工是否仍然都在？

### 结果特征

- 结果只有 `job_title` 一列；
- 每个非重复职位只显示一次；
- 原始员工记录不会改变。

### 最小修改任务

改为查询员工表中不重复的 `department_id`。

### 本例常见错误

- 把 `DISTINCT` 放在 `FROM` 后；
- 以为 `DISTINCT` 会删除原表重复数据；
- 查询多列后，只检查了其中一列是否重复。

## 示例 5：计算预算的百分之十

### 学习目标

理解查询可以生成计算列，但不会修改原始预算。

### 运行前预测

1. 结果会有多少列？
2. 计算列的值来自哪个字段？
3. `projects.budget` 会不会被改小？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name,
    budget,
    budget * 0.10 AS budget_ten_percent
FROM projects;
```

### 运行后观察

1. 计算列标题是什么？
2. 任选一行，计算值是否等于预算乘以 `0.10`？
3. 再查询 `budget` 时，原值是否保持不变？

### 结果特征

- 结果有三列；
- 每个项目都有一个计算结果；
- 计算列只存在于本次查询结果。

### 最小修改任务

把计算比例改为 `0.05`，别名改为 `budget_five_percent`。

### 本例常见错误

- 把 `10%` 直接写进 SQL；
- 忘记给计算列起别名；
- 误以为计算列会写回原表。

## 示例 6：查询薪资最高的三名员工

### 学习目标

组合指定列、多列排序和 `LIMIT`，得到顺序稳定的结果。

### 运行前预测

1. 结果会返回几列、最多几行？
2. `salary` 应按升序还是降序？
3. 如果两人薪资相同，第二排序列有什么作用？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_id,
    employee_name,
    salary
FROM employees
ORDER BY
    salary DESC,
    employee_id ASC
LIMIT 3;
```

### 运行后观察

1. 薪资是否从高到低？
2. 是否最多只有三行？
3. 相同薪资时，员工编号是否从小到大？

### 结果特征

- 结果有三列，最多三行；
- `salary` 从高到低；
- 相同薪资按 `employee_id` 从小到大，顺序可重复验证。

### 最小修改任务

把查询改成薪资最低的三名员工；相同薪资仍按 `employee_id` 升序。

### 本例常见错误

- 使用 `ASC` 查“最高”薪资；
- `LIMIT` 写在 `ORDER BY` 前；
- 没有为相同薪资设置第二排序列。

## 5. 容易混淆的地方

- `SELECT *` 能运行，不代表结果列符合题目要求。
- `AS` 只改变结果列标题，不修改原表字段名。
- `DISTINCT` 只影响查询结果，不会删除数据库里的重复数据。
- 计算列不会自动保存到表中。
- `LIMIT` 如果没有 `ORDER BY`，不代表“最高”或“最低”的前几条。

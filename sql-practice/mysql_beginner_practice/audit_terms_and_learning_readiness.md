## 当前结论

教材已经形成清楚的“理解 → 预测 → 运行 → 观察 → 最小修改 → 分层练习 → 错题重做 → 无提示测评”闭环。十章都具备 5～7 个可运行示例和 8 道分层练习，未发现练习提前要求尚未教授的 SQL 语法。

术语内容本身较完整，重点概念都能在对应章节或 `glossary.md` 找到通俗定义、易混点和学习位置；主要缺口不是“完全没讲”，而是 README 在读者已经遇到多个术语之后才首次提示术语表，以及独立测评没有明确禁止计时中查阅术语表。

## 示例、练习梯度和学习时长

- 每章含 5～7 个示例，每个示例均包含学习目标、运行前预测、独立代码块、运行后观察、结果特征、最小修改任务和常见错误；
- 每章 8 道正式练习，数量结构统一为 2 道模仿、3 道基础变形、2 道独立、1 道改错；
- 练习没有先于 lesson 使用尚未讲解的 SQL 语法；
- 第三级提示保留字段、条件或连接键空位，没有直接给出完整可运行答案；
- `answers.sql` 与练习分开，学习顺序能阻止初学者在正式练习前被动看到答案。

完整一章无法可靠地在 45～60 分钟内做完：8 题仅按每题最低 5 分钟已经需要至少 40 分钟，再加 lesson、示例、最小修改和错题整理，合理总时长约 65～90 分钟。README 和每章均明确说明“45～60 分钟是一个学习时段，不保证完成整章”，并建议拆成两个时段。这一表述诚实，不应为了形式上的 60 分钟压缩独立思考时间。

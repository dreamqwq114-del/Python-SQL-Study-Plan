## 1. 本章目标

- 使用 `WHERE` 保留满足条件的行。
- 使用 `AND`、`OR`、`NOT` 组合条件，并用括号表达意图。
- 使用 `IN`、`BETWEEN` 和 `LIKE` 写常见筛选。

## 2. 前置知识

## 3. 核心概念

### WHERE 与比较条件

#### 它解决什么问题

`WHERE` 从表中筛选行。只有条件结果为真时，该行才进入结果。

#### 最基本语法

```sql
SELECT column_name
FROM table_name
WHERE number_column >= 100;
```

#### 怎么理解

先决定从哪张表取哪些列，再在 `WHERE` 后写保留行的条件。常见比较符有 `=`、`<>`、`>`、`>=`、`<`、`<=`。

#### 常见错误

- 字符串或日期漏写单引号。
- 把 `=` 写成其他语言中的 `==`。

#### 如何验证结果

检查每一行是否满足条件，同时留意是否漏掉边界值。

### AND、OR、NOT 与优先级

#### 它解决什么问题

`AND` 要求多个条件同时成立，`OR` 要求至少一个成立，`NOT` 对条件取反。

#### 最基本语法

```sql
SELECT column_name
FROM table_name
WHERE (condition_a OR condition_b)
  AND condition_c;
```

#### 怎么理解

MySQL 先计算 `NOT`，再计算 `AND`，最后计算 `OR`。只要同时出现 `AND` 和 `OR`，就用括号明确分组。

#### 常见错误

- 忘记括号，使能运行的 SQL 返回错误结果。
- 重复写 `WHERE`，而不是用逻辑运算符连接条件。

#### 如何验证结果

分别检查每组条件，再确认所有返回行都符合括号表达的整体逻辑。

### IN

#### 它解决什么问题

`IN` 用一个条件匹配一组离散值。

#### 最基本语法

```sql
WHERE column_name IN ('A', 'B')
```

#### 怎么理解

`IN ('A', 'B')` 相当于“等于 A 或等于 B”，适合明确列举允许值。

#### 常见错误

- 漏写括号；
- 字符串值漏写单引号。

#### 如何验证结果

检查每一行是否都属于给定列表，并确认列表外的值没有出现。

### BETWEEN

#### 它解决什么问题

`BETWEEN` 筛选一个包含下限和上限的连续范围。

#### 最基本语法

```sql
WHERE number_column BETWEEN 100 AND 200
```

#### 怎么理解

它等价于 `number_column >= 100 AND number_column <= 200`，两个端点都会保留。

#### 常见错误

- 误以为范围不包含端点；
- 把较大的值写在前面。

#### 如何验证结果

检查最小值、最大值和边界值是否符合条件。

### LIKE

#### 它解决什么问题

`LIKE` 按文本模式筛选，`%` 表示任意长度文本，`_` 表示一个字符。

#### 最基本语法

```sql
WHERE text_column LIKE '%工程师'
```

#### 怎么理解

`'%工程师'` 表示以“工程师”结尾；`'工程师%'` 表示以它开头；`'%工程师%'` 表示任意位置包含。

#### 常见错误

- 把 `%` 放在错误的一侧；
- 忘记给模式加单引号。

#### 如何验证结果

逐行检查文本的开头、结尾或包含位置是否与模式一致。

### NULL 判断

#### 它解决什么问题

`NULL` 表示未知或缺失，必须使用 `IS NULL` 或 `IS NOT NULL` 判断。

#### 最基本语法

```sql
WHERE column_name IS NULL
WHERE column_name IS NOT NULL
```

#### 怎么理解

`NULL` 不是普通值，所以 `= NULL` 和 `<> NULL` 都不能得到想要的结果。

#### 常见错误

- 使用 `= NULL`。
- 把空字符串 `''` 与 `NULL` 当成同一件事。

#### 如何验证结果

查看目标列，确认所有返回行确实为空或非空，并比较两类行数是否合理。

## 4. 可运行示例

## 示例 1：筛选高薪员工

### 学习目标

用一个数值条件理解 `WHERE` 只筛选行、不改变返回列。

### 运行前预测

1. 结果有几列？
2. 薪资等于 15000 的员工会不会返回？
3. 是否还会返回所有员工？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    salary
FROM employees
WHERE salary >= 15000;
```

### 运行后观察

1. 每行薪资是否都不低于 15000？
2. 边界值 15000 是否被包含？
3. 原员工表行数是否改变？

### 结果特征

- 只有两列；
- 只返回满足薪资条件的员工；
- 原表不会被修改。

### 最小修改任务

改为筛选薪资低于 10000 的员工。

### 本例常见错误

- 把 `>=` 写成 `>`，漏掉边界；
- 在 `FROM` 前写 `WHERE`；
- 误以为查询会删除未返回的员工。

## 示例 2：组合部门和薪资条件

### 学习目标

理解 `AND` 要求两个条件同时成立。

### 运行前预测

1. 部门编号为 2 但薪资不足 12000 的员工会不会返回？
2. 其他部门的高薪员工会不会返回？
3. 结果会有几列？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    department_id,
    salary
FROM employees
WHERE department_id = 2
  AND salary >= 12000;
```

### 运行后观察

1. 每行是否同时满足两个条件？
2. 去掉 `AND salary >= 12000` 后，行数如何变化？
3. 是否出现其他部门？

### 结果特征

- 结果有三列；
- 每行 `department_id` 都是 2；
- 每行薪资都不低于 12000。

### 最小修改任务

将部门改为 3，并将最低薪资改为 10000。

### 本例常见错误

- 写两个 `WHERE`；
- 把 `AND` 误写成 `OR`；
- 只验证其中一个条件。

## 示例 3：用括号组合 AND 与 OR

### 学习目标

理解括号如何明确复杂条件的计算顺序。

### 运行前预测

1. 哪两个项目状态可以通过第一组条件？
2. 预算不满 600000 的项目会不会返回？
3. 去掉括号后含义是否相同？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name,
    project_status,
    budget
FROM projects
WHERE (project_status = '进行中' OR project_status = '待启动')
  AND budget >= 600000;
```

### 运行后观察

1. 每行状态是否属于两种目标状态？
2. 每行预算是否都达到 600000？
3. 去掉括号后是否可能混入低预算的“进行中”项目？

### 结果特征

- 结果只有目标状态；
- 所有预算都达到下限；
- 括号让业务条件一眼可见。

### 最小修改任务

把两种状态改为“已完成”和“暂停”，预算下限改为 300000。

### 本例常见错误

- 混合 `AND`、`OR` 时不加括号；
- 字符串漏写单引号；
- SQL 能运行就认为逻辑一定正确。

## 示例 4：使用 IN 筛选多个部门

### 学习目标

使用一个条件列出多个允许的部门编号。

### 运行前预测

1. 部门编号允许哪些值？
2. 部门 1 的员工会不会返回？
3. 结果中会不会出现部门 2 和 5 以外的编号？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    department_id
FROM employees
WHERE department_id IN (2, 5);
```

### 运行后观察

1. 是否出现部门 2 或 5 以外的员工？
2. 两个目标部门是否都有员工返回？
3. `IN (2, 5)` 可以怎样用 `OR` 表达？

### 结果特征

- 结果只有两列；
- 部门只来自给定列表；
- 原表记录不会被修改。

### 最小修改任务

将部门列表改为 1 和 4。

### 本例常见错误

- 把 `IN (2, 5)` 写成 `IN 2, 5`；
- 重复写两个 `WHERE`；
- 字符串列表中的文本漏写引号。

## 示例 5：使用 BETWEEN 筛选薪资范围

### 学习目标

观察 `BETWEEN` 会包含上下两个边界。

### 运行前预测

1. 薪资 9000 会不会返回？
2. 薪资 13000 会不会返回？
3. 低于 9000 的薪资会不会返回？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    salary
FROM employees
WHERE salary BETWEEN 9000 AND 13000
ORDER BY salary ASC;
```

### 运行后观察

1. 最低和最高返回薪资是多少？
2. 边界值是否被保留？
3. 所有薪资是否都在闭区间内？

### 结果特征

- 结果只有姓名和薪资两列；
- 薪资在 9000 到 13000 之间，包含端点；
- 结果按薪资升序，方便核对范围。

### 最小修改任务

将薪资范围改为 9500 到 13500。

### 本例常见错误

- 把较大边界写在前面；
- 误以为不包含端点；
- 在两个边界之间漏写 `AND`。

## 示例 6：使用 LIKE 筛选职位后缀

### 学习目标

理解 `%` 在模式左侧表示“以指定文本结尾”。

### 运行前预测

1. 职位必须以哪个文本结尾？
2. “测试工程师”会不会匹配？
3. “项目专员”会不会匹配？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    job_title
FROM employees
WHERE job_title LIKE '%工程师';
```

### 运行后观察

1. 每个职位是否都以“工程师”结尾？
2. 普通“工程师”和“测试工程师”是否都能匹配？
3. 把模式改成 `'工程师%'` 后含义会怎样变化？

### 结果特征

- 结果只有姓名和职位两列；
- 所有职位都以“工程师”结尾；
- `%` 只影响查询匹配，不修改文本。

### 最小修改任务

改为筛选职位中任意位置包含“专员”的员工。

### 本例常见错误

- 把模式写成 `'工程师%'`；
- 漏写单引号；
- 忘记 `%` 的位置决定开头、结尾或包含。

## 示例 7：筛选缺少结束日期的项目

### 学习目标

正确使用 `IS NULL`，并用 `NOT IN` 排除状态。

### 运行前预测

1. `end_date = NULL` 能否得到相同结果？
2. 哪一列会全部显示为 `NULL`？
3. 已完成项目会不会返回？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name,
    project_status,
    end_date
FROM projects
WHERE end_date IS NULL
  AND project_status NOT IN ('已完成');
```

### 运行后观察

1. 所有 `end_date` 是否都为空？
2. 是否出现“已完成”状态？
3. 改成 `IS NOT NULL` 后结果含义如何变化？

### 结果特征

- 结果有三列；
- 返回行的 `end_date` 都是 `NULL`；
- 已完成项目被排除。

### 最小修改任务

改为查询结束日期非空，并且状态不是“暂停”的项目。

### 本例常见错误

- 使用 `= NULL`；
- 把 `NOT` 放错位置；
- 只检查状态，没有检查空值。

## 5. 容易混淆的地方

- `WHERE` 过滤的是行，不决定显示哪些列。
- `BETWEEN` 包含两个端点。
- `AND` 的优先级高于 `OR`，复杂条件应使用括号。
- `LIKE '%工程师'` 表示以“工程师”结尾，`LIKE '%工程师%'` 表示任意位置包含。
- `NULL` 不能使用 `= NULL`；空字符串也不等于 `NULL`。

# 第 3 章：排序和日期

## 本章计时建议

## 1. 本章目标

- 使用 `ORDER BY`、`ASC` 和 `DESC` 控制结果顺序。
- 使用多列排序处理相同值，使结果稳定。
- 对日期、数值和文本字段写筛选条件。
- 先用 `WHERE` 筛选，再对保留的行排序。
- 暂时不学习日期函数、分组和表连接。

## 2. 前置知识

需要会使用 `SELECT`、`FROM`、`WHERE` 和常见比较条件。

## 3. 核心概念

### ORDER BY、ASC 与 DESC

#### 它解决什么问题

`ORDER BY` 明确结果的排列规则。`ASC` 从小到大，`DESC` 从大到小。

#### 最基本语法

```sql
SELECT column_name
FROM table_name
ORDER BY sort_column DESC;
```

#### 怎么理解

数字按大小、日期按先后、文本按数据库排序规则排列。省略方向时默认是 `ASC`，初学时建议写出来。

#### 常见错误

- 把 `ORDER BY` 写在 `WHERE` 前。
- 把 `DESC` 写在字段名前。

#### 如何验证结果

检查相邻两行是否符合方向；不要只看第一行。

### 多列排序

#### 它解决什么问题

当第一排序列相同时，第二排序列决定这些并列行的顺序。

#### 最基本语法

```sql
ORDER BY
    first_column DESC,
    second_column ASC;
```

#### 怎么理解

先按第一列分出大顺序，只在第一列相同的行之间使用第二列。

#### 常见错误

- 以为第二列会打乱第一列的整体顺序。
- 多个排序列之间漏写逗号。

#### 如何验证结果

重点找第一排序值相同的行，检查第二列是否按要求排列。

### 日期、数值与文本条件

#### 它解决什么问题

`WHERE` 可以比较不同类型的字段，但值的写法要符合字段类型。

#### 最基本语法

```sql
WHERE date_column >= '2024-01-01'
WHERE number_column < 100
WHERE text_column = '进行中'
```

#### 怎么理解

MySQL 日期建议写成 `'YYYY-MM-DD'`。文本和日期使用单引号，数值通常不加引号。

#### 常见错误

- 日期使用模糊格式，如 `'01/02/24'`。
- 文本漏写单引号。
- 把日期比较理解成字符串随意比较。

#### 如何验证结果

查看边界值是否包含，逐行确认日期、数值或文本确实满足条件。

### WHERE 与 ORDER BY 的执行关系

#### 它解决什么问题

先筛选需要的行，再决定这些行的显示顺序。

#### 最基本语法

```sql
SELECT column_name
FROM table_name
WHERE condition
ORDER BY sort_column ASC;
```

#### 怎么理解

书写顺序是 `FROM`、`WHERE`、`ORDER BY`。排序不会让不满足 `WHERE` 的行重新出现。

#### 常见错误

- 把 `WHERE` 写到 `ORDER BY` 后。
- 只验证排序，不验证筛选。

#### 如何验证结果

先确认所有行满足筛选，再检查它们的相邻顺序。

## 4. 可运行示例

## 示例 1：按入职日期查看员工

### 学习目标

使用日期列升序，理解最早日期排在前面。

### 运行前预测

1. 结果有几列？
2. 最早入职的员工会在前面还是后面？
3. 省略 `ASC` 时方向是否改变？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    hire_date
FROM employees
ORDER BY hire_date ASC;
```

### 运行后观察

1. 日期是否从早到晚？
2. 相邻日期是否出现倒退？
3. 是否仍返回所有员工？

### 结果特征

- 结果有两列；
- 入职日期从早到晚；
- 排序不删除任何行。

### 最小修改任务

改为按入职日期从晚到早排列。

### 本例常见错误

- 把 `ASC` 理解为从晚到早；
- 将 `ORDER BY` 写成 `ORDER`；
- 只查看第一行，不检查整体顺序。

## 示例 2：用多列排序稳定员工名单

### 学习目标

理解第一排序列相同时才使用第二排序列。

### 运行前预测

1. 员工先按哪一列分组排列？
2. 同一部门内薪资高的人排在哪里？
3. 第二列会不会让部门编号顺序混乱？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    department_id,
    salary
FROM employees
ORDER BY
    department_id ASC,
    salary DESC;
```

### 运行后观察

1. 部门编号是否从小到大？
2. 每个部门内部薪资是否从高到低？
3. 是否需要查看多个部门才能验证？

### 结果特征

- 部门顺序为升序；
- 同一部门内按薪资降序；
- 第二排序列不跨部门改变顺序。

### 最小修改任务

保持部门升序，把部门内部改为薪资从低到高。

### 本例常见错误

- 排序列间漏写逗号；
- 误以为两个方向只能相同；
- 只检查薪资，没有检查部门。

## 示例 3：筛选指定日期之后入职的员工

### 学习目标

正确书写日期常量，并理解 `>=` 包含边界日期。

### 运行前预测

1. 在 2023-01-01 当天入职的人是否返回？
2. 日期需要单引号吗？
3. 结果是否按日期自动排序？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    employee_name,
    hire_date
FROM employees
WHERE hire_date >= '2023-01-01'
ORDER BY
    hire_date ASC,
    employee_id ASC;
```

### 运行后观察

1. 是否存在早于边界日期的行？
2. 日期是否从早到晚？
3. 相同日期时是否按员工编号稳定排序？

### 结果特征

- 日期不早于 2023-01-01；
- 结果按日期升序；
- `WHERE` 筛选与 `ORDER BY` 排序各有作用。

### 最小修改任务

改为查询 2022-01-01 之前入职的员工，并按日期从晚到早排列。

### 本例常见错误

- 日期漏写单引号；
- 把 `>=` 写成 `>`，改变边界；
- 以为 `WHERE` 会自动排序。

## 示例 4：按预算筛选并排序项目

### 学习目标

复习数值条件，并将筛选后的项目按预算稳定排序。

### 运行前预测

1. 预算等于 500000 的项目是否返回？
2. 预算最高的行位于哪里？
3. 相同预算如何决定顺序？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name,
    budget
FROM projects
WHERE budget >= 500000
ORDER BY
    budget DESC,
    project_id ASC;
```

### 运行后观察

1. 是否所有预算都达到下限？
2. 预算是否从高到低？
3. 并列时项目编号是否升序？

### 结果特征

- 只返回达标项目；
- 预算从高到低；
- 相同预算有稳定顺序。

### 最小修改任务

把预算下限改为 700000，并按预算从低到高排列。

### 本例常见错误

- 数值写错一个零；
- 筛选用 `>=`，排序方向却理解反了；
- 忘记第二排序列。

## 示例 5：筛选状态并按日期排序

### 学习目标

组合文本条件和日期排序，观察 `NULL` 在升序中的位置。

### 运行前预测

1. 是否只返回“待启动”项目？
2. 最早计划开始的项目排在哪里？
3. `end_date` 的 `NULL` 是否影响本次排序？

### 示例代码

```sql
USE mysql_beginner_practice;

SELECT
    project_name,
    project_status,
    start_date,
    end_date
FROM projects
WHERE project_status = '待启动'
ORDER BY
    start_date ASC,
    project_id ASC;
```

### 运行后观察

1. 状态列是否全部一致？
2. 开始日期是否从早到晚？
3. 结果中的 `end_date` 是否可能有 `NULL`？

### 结果特征

- 状态全部为“待启动”；
- 按开始日期升序；
- 显示 `NULL` 不等于按该列筛选。

### 最小修改任务

改为查询“进行中”项目，并按开始日期从晚到早排列。

### 本例常见错误

- 文本漏写单引号；
- 错把 `end_date` 当作排序列；
- 看到 `NULL` 就以为查询错误。

## 5. 容易混淆的地方

- `ORDER BY` 只改变结果顺序，不修改表中存储顺序。
- `ASC` 是从小到大、从早到晚；`DESC` 相反。
- 多列排序按从左到右的优先级处理。
- `WHERE` 负责筛选，`ORDER BY` 负责排序，书写顺序不能交换。
- 日期建议使用 `'YYYY-MM-DD'`，边界是否包含由比较符决定。
